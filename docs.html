Build a plugin for Mosaic, test it, and share it through the Plugin store.

Plugin API

Plugins extend Mosaic on the website and in the desktop/mobile app with the same code. A plugin can add toolbar buttons, side panels, command-palette commands, settings sections and export formats, react to events, and read or change the project (when the user allows it). You can share a plugin with everybody through the Plugin store.

Plugins are trusted code. They run inside the page with the same access as Mosaic itself. The permissions below limit the plugin API and are shown to the user, but they are not a security sandbox. Reviewers read every store plugin before it is listed; users should still only turn on plugins they trust.

Quick start

A plugin is one JavaScript file plus a manifest. This one adds a toolbar button that counts the items on the page:

Mosaic.plugin({
  id: 'item-counter',                      // must match the manifest
  activate(api) {
    api.toolbar.add({
      label: 'Count', title: 'Count the items on this page', where: 'any',
      run: () => api.toast(api.project.items().length + ' items on this page')
    });
  }
});

{
  "id": "item-counter",
  "name": "Item counter",
  "version": "1.0.0",
  "apiVersion": 1,
  "author": "You",
  "description": "Adds a button that counts the items on the page.",
  "permissions": ["project.read", "ui.toolbar"]
}

To try it locally put both in your plugins folder (see below). To share it, use Settings → Plugins → Submit a plugin.

Where plugins come from

Source How it gets there
Plugin store Anyone with an account submits it, a reviewer approves it, anyone can install it from Settings → Plugins → Plugin store. Installed copies live on the user's device and are re-checked against the approved SHA-256 every time Mosaic starts.
Bundled (website) A folder under plugins/ listed in plugins/index.json.
User folder (desktop/mobile app) A folder with manifest.json and its scripts in the app's plugins folder (shown in Settings → Plugins). Press Reload plugin list.

For bundled and user-folder plugins the manifest also needs "entry": "my-plugin/main.js" (relative to plugins/, or to the plugin folder in the app). Store plugins do not have an entry: the code is stored with the submission.

Manifest

Field Required Meaning
id yes 3 to 41 characters: a-z, 0-9, -. Must match the id in Mosaic.plugin({ id }). First come, first served in the store; only the person who owns an id can publish new versions of it.
name yes Shown to users (up to 60 characters).
version yes 1.0.0 style. Raise it for every new submission.
apiVersion no The plugin API you built against (currently 1).
author, description no (store: description required) Shown in the store. Description: 10 to 400 characters.
permissions no What the plugin asks for (list below). Users see this before installing.
hosts with network Servers it may contact: https://api.example.com, or http://127.0.0.1:* for any port on this computer.
userHosts no true lets the user approve extra https servers one by one (for example a custom AI provider).

Lifecycle

Mosaic.plugin({
  id: 'my-plugin',
  activate(api) { /* called when the user turns it on */ },
  deactivate() { /* optional cleanup; everything registered through `api` is removed for you */ }
});

Each plugin gets its own api object. Everything you register through it (toolbar buttons, panels, commands, settings, hooks, event listeners) is removed automatically when the user turns the plugin off or uninstalls it.

Permissions

Permission Lets the plugin
project.read read the current page, its items, the selection, the page list and page text (copies)
project.write update or add items, add pages, append to docs
ui.toolbar add buttons to the top toolbar
ui.settings add a section to its card in Settings → Plugins
ui.panel add a docked side panel
ui.commands add commands to the command palette (Ctrl+Shift+P)
export.targets add an export format
export.hooks modify the export manifest
storage keep small settings of its own (api.storage)
network call servers through api.fetch (see Network access)

Ask only for what you use. Reviewers reject plugins that ask for more than they need.

API reference (api)

General - api.version : the Mosaic version. - api.on(event, fn) : events: page:open, item:put, export:before, export:done, comment:added, page:created, prefs:change, plugins:changed. - api.toast(text) : a short message at the bottom of the screen. - api.prefs.get(path, default) : read Mosaic preferences (read only). - api.storage.get(key, default), .set(key, value), .remove(key) : per-plugin storage on this device (storage). Values are JSON. It is never synced to the user's account, so it is the right place for API keys.

Project (project.read unless noted) - api.project.page() : { id, name, type: 'b' | 'd' | 't', kind } for the open page. - api.project.items(), .selection() : copies of the items on the page / the selected items. - api.project.pages() : [{ id, name, type: 'board' | 'doc' | 'table', parent }]. - api.project.pageText(pageId, maxChars) : the text of a page as plain text. - api.project.search(query, max) : matching lines across all pages. - api.project.updateItem(id, patch), .addItem(obj) (project.write). addItem accepts p to target another page. - api.project.addPage({ name, type: 'board' | 'doc' | 'table' }) (project.write) : returns the new page id. - api.project.appendDoc(pageId, [{ t, x }]) (project.write) : t is p, h1, h2, h3, todo, q or code; x is the text. - api.project.openPage(pageId), .select(itemIds) : open a page, or select items on the open page. - api.project.table(pageId) : { columns, rows } for a table page. api.project.addTableRows(pageId, rows) (project.write) : rows is an array of arrays; returns how many were added. - api.project.renamePage(pageId, name), .deleteItem(id) (project.write) : locked items cannot be deleted. Deleting an item also removes its connectors. - api.project.snapshot() : { pages, items }, copies of the whole project, for backups and reports.

User interface - api.toolbar.add({ label, icon, title, where: 'design' | 'any', run }) (ui.toolbar) : icon is optional, the name of a built-in icon such as 'star' or 'download'. - api.ui.panel({ id, title, render(element), onOpen, onClose }) (ui.panel) : returns { open, close, toggle, isOpen, el }. Draw your UI into element. - api.commands.add({ id, title, hint, group, run }) (ui.commands) : appears in the command palette. - api.settings.add({ title, render(element) }) (ui.settings) : a section on your card in Settings → Plugins. - api.ui.confirm(text, { title, ok, cancel }) : an animated yes/no dialog; resolves to true or false. No permission needed. - api.ui.prompt(label, default, { title, ok, multiline }) : asks for text; resolves to the text, or null if cancelled. - api.ui.modal({ title, render(element, close), buttons }) (ui.panel) : a dialog with your own content. Each button is { label, primary, value, run(element, close), keepOpen }. Returns { close(value), closed }, where closed is a promise.

Environment and helpers - api.env.isTouch, .isPhone, .isApp, .readOnly, .theme ('light' or 'dark') : read these at the moment you need them; they stay current if the window is resized or the theme changes. - api.clipboard.writeText(text) : copy text; resolves to true or false. Browsers only allow it right after a click or tap. - api.download(name, data, mime) (export.targets) : save a file from a string, Uint8Array or Blob.

Export - api.hooks.add('export:manifest', (layout, ctx) => layout) (export.hooks) : may return a modified layout. - api.exports.addTarget({ id, label, build(ctx) }) (export.targets) : ctx = { layout, files, design, format }. files is an array of { name, data } (data is a Uint8Array or string). Push extra files, or return a replacement array. The result is zipped and saved.

Network (network) - api.fetch(url, init) : like fetch, but only for allowed servers (next section). - api.network.isAllowed(url), await api.network.request(url), api.network.approved(), api.network.revoke(origin).

Network access

api.fetch only allows: 1. the addresses in the manifest's hosts, and 2. if the manifest sets "userHosts": true, https servers the user approved. Call await api.network.request(url) before using a new server: Mosaic asks the user once, remembers the origin, and Settings lets them revoke it.

Plain http works only for this computer (http://127.0.0.1:*, http://localhost:*). Use api.fetch, never fetch, XMLHttpRequest or WebSocket directly: direct calls skip the user's approval and reviewers will reject them.

The page's Content-Security-Policy (connect-src in app.html, _headers and kCsp in src/AssetServer.cpp) allows any https host plus localhost, so that plugins can reach providers the user picks. That means the policy itself no longer limits where a script on the page can send data: the manifest list and the per-server approval are the guard. Site operators who do not want this can replace https: in connect-src with a fixed list of hosts. Store plugins are loaded from blob: URLs, which is why script-src contains blob:.

Writing good plugins

  • Escape text from projects before putting it into innerHTML (or use textContent). Project text can contain anything.
  • Use Mosaic's CSS variables (var(--bg), var(--tx), var(--bd), var(--ac), var(--hv), var(--mu)) so your UI follows light and dark themes.
  • Make controls reachable with the keyboard and give buttons labels (aria-label).
  • Ask before changing the user's project, and make changes easy to see. Never send project text anywhere unless the user asked.
  • Keep secrets (API keys) in api.storage, never in your code.
  • Do not touch other parts of the page, the login session or localStorage directly. Anything that needs more than the API belongs in a feature request.

Publishing to the Plugin store

  1. Open Settings → Plugins → Submit a plugin (you need an account; guests can browse and install but not submit).
  2. Fill in the form or load your manifest.json and main.js. Press Check: it validates the manifest, matches the id in your code, and shows the automatic scan a reviewer will see.
  3. Submit for review. Your plugin is pending and visible only to you and to reviewers. Follow it under My submissions.
  4. A reviewer (the owner or anyone with Dev tools) reads the code and approves or rejects it with a note. Approved plugins appear in the store for everyone.
  5. To change anything, submit a new version (raise version). Submitted code can never be edited, so what was reviewed is exactly what people install.

Limits: code up to 300,000 characters, one JavaScript file, at most 5 submissions waiting at once, description 10 to 400 characters. Pending and rejected submissions can be deleted by you at any time. Approved plugins can be removed by reviewers (for example if a problem turns up); people who installed it see "no longer in the store" next time they open the store.

What reviewers check

  • It does what the description says and nothing else.
  • Permissions and hosts are the minimum needed; userHosts only when users really choose their own servers.
  • All network access goes through api.fetch; nothing reads the login session, cookies or other storage; no eval or new Function; no loading of other scripts; no navigation or pop-ups.
  • Text from projects is escaped; changes to projects are announced or confirmed.
  • No hidden behaviour, no tracking, no obfuscated or minified-beyond-reading code.

The review screen runs an automatic scan (network calls outside api.fetch, account access, eval, direct storage, HTML injection…) and highlights the lines. The scan helps; it does not replace reading the code.

Dialogs, phones and touch

Mosaic runs on phones too, so build for small screens from the start.

  • Use api.ui.confirm, api.ui.prompt and api.ui.modal instead of alert, confirm and prompt. They animate, trap the Escape key, and turn into bottom sheets on phones.
  • Check api.env.isPhone before you put a wide layout in a panel. Panels take the full screen width on phones.
  • Make tap targets at least 44 px tall, and never rely on hover.
  • Use Mosaic's colour variables (var(--tx), var(--mu), var(--bd), var(--hv), var(--pn), var(--ac)) so your UI follows light and dark mode.

Recipes

Ask before you change something

api.commands.add({ id: 'clean', title: 'Delete empty notes', run: async () => {
  const empty = api.project.items().filter(i => i.ty === 'note' && !String(i.t || '').trim());
  if (!empty.length) return api.toast('No empty notes.');
  if (!await api.ui.confirm('Delete ' + empty.length + ' empty notes?', { ok: 'Delete' })) return;
  empty.forEach(i => api.project.deleteItem(i.id));
} });

Export a table as CSV (needs project.read and export.targets)

api.commands.add({ id: 'csv', title: 'Download this table as CSV', run: () => {
  const page = api.project.page();
  if (!page || page.type !== 'table') return api.toast('Open a table page first.');
  const t = api.project.table(page.id);
  const q = v => '"' + String(v).replace(/"/g, '""') + '"';
  api.download(page.name + '.csv', [t.columns, ...t.rows].map(r => r.map(q).join(',')).join('\n'), 'text/csv');
} });

Show a dialog with your own content

api.ui.modal({ title: 'Project summary',
  render(el) { el.textContent = api.project.pages().length + ' pages'; },
  buttons: [{ label: 'Copy', run: () => api.clipboard.writeText('Pages: ' + api.project.pages().length), keepOpen: true }, { label: 'Close', primary: true }] });

API versions

The plugin API is versioned with apiVersion in your manifest. Version 2 adds the dialogs, api.env, api.clipboard, api.download, toolbar icons, and the extra api.project methods above. Version 1 plugins keep working unchanged. A plugin that sets apiVersion: 2 will be refused by an older Mosaic with a message asking the user to update.

Reference plugins

  • plugins/example-asset-report : a bundled example that adds an export format.
  • store-plugins/ai-assistant : the AI assistant & MCP plugin (Ollama, Claude, ChatGPT and more; MCP tool servers). It uses panels, commands, settings, network with userHosts, and shows how to ask before changing a project.

Item data exported for engines

Engine integrations (Unity, Godot, Unreal) are meant to be built as plugins using this API. The data they need is already exported: layout.json (schema mosaic.ui-layout/1) with positions, sizes, pivots, 9-slice borders, and an optional sprite atlas (atlas.json). Each asset has name, x, y, w, h (px, origin top-left, y down), pad, pivot {x,y} (0-1), optional nineSlice {l,t,r,b}, and files per scale. Items carry these extra properties for plugins: xn (export name), nx (skip export), sl (9-slice [l,t,r,b]), pv (pivot name).

Setting up the store (site operators)

Run setup/plugin-store.sql once in the central Supabase (after central-setup.sql). It creates the mosaic_plugins table, row-level security (anyone reads approved plugins; signed-in users submit; only developers review) and freezes submitted code. Optionally run setup/seed-ai-assistant.sql to publish the AI assistant plugin as an approved plugin.
